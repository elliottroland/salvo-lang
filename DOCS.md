# DOCS.md — working document for `salvo docs` and the documentation rewrite

A working document (user request 2026-10-30): the plan, the decisions and where
the work is, so a session that lost its context can pick up. When the work is
done, retire it as AGENTS.md says: open items to ROADMAP.md, the record to
COMPLETED.md, then delete this file.

## The request (user, 2026-10-30)

1. **`salvo docs`**: collect the doc comments on modules, fns, types, effects,
   handlers, qualifiers, groups; write pages with an index and a way to find
   things; render code examples; include `docs/language/` as an overview.
2. **Output is GitHub-wiki Markdown** (GitHub serves no `.html` pages and strips
   scripts, `style` and `class`; user accepted 2026-10-30). Consequences:
   - code is fenced ```` ```rust ```` (GitHub cannot highlight Salvo); sources
     write ```` ```salvo ```` and the generator rewrites the fence;
   - "search" is a generated A–Z `Index` page plus GitHub's own wiki search;
   - HTML only where GitHub allows it (tables, `<details>`, anchors).
   Written into `wiki/` for the repository (a separate git repo; never commit
   there — the user commits it; `git -C wiki reset --hard` restores it).
3. **`[docs]` manifest section**: `out` (directory), `home` (one file, the
   wiki's `Home`), `topics` (a directory of pages). Nothing special for the
   wiki case: std's manifest (`lib/salvo.toml`) carries it, so `cd lib &&
   salvo docs` regenerates the wiki. `salvo docs --check` replaces
   `tools/sync-wiki.sh` (deleted) and the docs test uses it.
4. **Rule labels leave std's comments**: no `[rule-label]` in prose; doc blocks
   keep them only in `// @compilerrules [...]` lines (hidden by the renderer);
   comments inside fn bodies keep theirs (they are for compiler maintainers).
5. **Rewrite std's doc comments** for someone who does not know Salvo's
   internals — Java's `ConcurrentHashMap` docs as the model: what it is, how
   it behaves, its guarantees and costs, examples. Examples in module docs and
   for functions and actors; more detail for the runtime; module docs show the
   module's types and functions in use.
6. **Rewrite `docs/language/` as a narrative**: each topic opens with an
   overview of the feature; later sections are caveats, exceptions,
   extensions. Topics may now point at module/type pages.
7. **Later, not now** (user): examples in docs "compiled", errors as warnings
   at compile time, LSP hover on them like ordinary code. Leave a ROADMAP item.

## Design decisions (mine, within the user's)

- **Pages**: `Home` (from `home`), one page per topic (the file name, as now:
  `Data-and-Types.md`), one page per module named with dashes
  (`std-core-list.md`, title "std core list"; dots in wiki page names are
  unreliable), `Index.md` (every documented name A–Z with kind, module and its
  first sentence), `_Sidebar.md` (Overview: Home + topics in the order `home`
  links them, the rest alphabetically; Library: modules grouped by their first
  two segments inside `<details>`; Index), `_Footer.md` (generated-by line).
- **Every generated page starts with** `<!-- Generated by salvo docs from …;
  edit the source, not this page. -->`. A topic loses its first `# Title`
  (the wiki titles a page by its file), and `](Foo.md)` links lose `.md`.
- **A link to a `.sv` file** (relative to the topic, e.g.
  `../../lib/std/core/seq.sv#map`) becomes a link to that module's page, so a
  topic links the API in the repository and in the wiki alike.
- **Module page layout**: `Module std.core.seq`, the module docs, a contents
  table (kind, name, summary), then sections Types / Effects / Handlers /
  Qualifiers / Groups / Functions; each entry a `###` heading (GitHub makes the
  anchor: lowercase, punctuation dropped, spaces to `-`), its signature in a
  `rust` fence, its docs. Overloads of one name share a heading. Only exported
  declarations; `@compilerrules`/`@compilerknown` hidden; `@param` and other
  tags rendered as a list.
- **`[symbol]` in a doc comment** links: a local name (param, field, generic)
  stays `` `code` ``; a name declared in the documented set links to its page
  and anchor; anything else is `` `code` ``.
- **Which modules**: the project's own files (std for std's manifest). No
  dependencies.

## Notes for whoever picks this up

- Run std's docs: `cd lib && ../target/debug/salvo docs` (writes `../wiki`).
- Edits can land after the next command: check text in the same shell command
  as a build (`grep -c 'new' f && touch f && cargo build`).
- After editing std `.sv`: `touch crates/salvo-cli/src/analysis.rs` before
  building (the embed), and `zsh tmp/regen.sh` before the suite.
- The test `std_docs_cite_rules_only_in_compilerrules` already polices doc
  blocks; module headers and body comments are where labels remain.
