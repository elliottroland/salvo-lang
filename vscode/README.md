# Salvo for VS Code

Syntax highlighting and language-server support (diagnostics + type-on-hover)
for the Salvo programming language (see `README.md` and `LANGUAGE.md` at the
repository root). The language server is the `salvo` compiler itself, started
as `salvo lsp` over stdio.

## Build and install

```bash
cd vscode
npm install
npm run compile
```

Then either launch an Extension Development Host (open `vscode/` in VS Code
and press F5), or package and install it:

```bash
npx @vscode/vsce package   # produces salvo-vscode-<version>.vsix
code --install-extension salvo-vscode-*.vsix
```

## Pointing at your salvo binary

The extension spawns the binary named by the `salvo.serverPath` setting
(default: `salvo` on PATH). While hacking on the compiler, point it at the
build output — relative paths resolve against the workspace folder:

```jsonc
// .vscode/settings.json in the salvo-lang repo
{
  "salvo.serverPath": "target/debug/salvo",
  "salvo.backend": "" // or "kotlin" / "rust" to include that backend's define files
}
```

After `cargo build`, run **Salvo: Restart Language Server** from the command
palette to pick up the new binary (changing either setting also restarts it
automatically).

## Regenerating the grammar

`syntaxes/salvo.tmLanguage.json` is generated by the compiler so keyword
highlighting can never drift from the lexer:

```bash
cargo run -- lang tm-grammar --out vscode/syntaxes/salvo.tmLanguage.json
```

A test in `salvo-cli` (`vscode_extension_grammar_is_up_to_date`) fails if the
checked-in file is stale.

## Note on `.sv`

Salvo uses the `.sv` extension, which SystemVerilog extensions also claim.
If both are installed, pick the language per-file ("Change Language Mode")
or associate it per-workspace:

```jsonc
{ "files.associations": { "*.sv": "salvo" } }
```
